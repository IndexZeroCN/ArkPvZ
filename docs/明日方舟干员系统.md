# 明日方舟干员系统

本文档介绍《植物大战僵尸 × 明日方舟》同人中的干员系统：架构、实现约定、动画管线、克洛丝数值与后续计划（维什戴尔等）。

## 1. 总体设计

### 1.1 干员 = PlantType 子集

干员**注册为 `CharacterRegistry.PlantType` 枚举**（P050 起，见 `scripts/autoload/global/character_registry.gd`），场景继承完整植物管线：

```
Character000Base
└── Plant000Base          (scenes/character/plant/plant_000_base.tscn)
    └── Operator000Base   (scenes/character/operator/operator_000_base.tscn)
        └── Summon000Base (scenes/character/operator/summon_000_base.tscn)
```

这样干员天然获得：卡片→手持→种植→植物格子（`PlantCell`）→被僵尸啃食→行渲染/斜面等全部能力，**与植物友方**（同一受击检测层、植物子弹不会误伤）。

- 干员类型列表：`CharacterRegistry.OperatorPlantType`，判断函数 `CharacterRegistry.is_operator_type(plant_type)`
- 干员卡片标记：`CardBase.is_operator_card`（消耗**部署点数**而非阳光）
- 可选干员白名单：`Global.global_game_state.curr_operator`（决定选卡界面干员页显示哪些）

### 1.2 部署点数（DP）

与明日方舟一致，干员消耗独立的**部署点数**，随时间自动回复，不消耗阳光：

- 管理器：`OperatorManager`（`scripts/manager/operator_manager/operator_manager.gd`，挂在主游戏 `Manager` 节点下）
- 关卡参数（`ResourceLevelData`，默认值）：
  - `is_can_use_operator = true`：本关卡是否允许干员
  - `operator_start_deploy_point = 10`：初始部署点数
  - `operator_max_deploy_point = 99`：上限
  - `operator_regen_interval = 2.0`：回复间隔（秒，≤0 不回复）
  - `operator_retreat_refund_ratio = 0.7`：撤退返还比例
- 变更广播：`EventBus.push_event("update_deploy_point", [value])`，出战卡槽（`CardSlotBattle`）订阅后更新右上角 DP 数字并刷新干员卡片可点击状态
- 测试模式（`main_game.is_test`）初始 DP 直接满额，便于调试

### 1.3 技能系统（SkillComponent）

`scripts/character/components/skill_component/component_skill.gd`，挂在干员头顶（HP 条上方），常显：

- `max_sp`：技能条上限（技能消耗）
- 回复方式 `E_SpRecoveryType`：`Attack`（攻击回复，每次攻击 +`sp_gain_per_attack`）/ `Time`（时间回复）/ `None`
- `is_auto_trigger`：就绪后是否自动触发
- 信号：`signal_skill_ready` / `signal_skill_use` / `signal_sp_change`

技能触发流程：`Operator000Base.use_skill()` → `SkillComponent.use_skill()` → 播放 `skill` 动画 → 调用虚钩子 `_on_skill_use()`（子类重写实现技能效果）。

### 1.4 血条与技能条（明日方舟风格）

干员的血条/技能条与植物僵尸不同，为头顶**迷你条**：

- 血条：15×2 px，**蓝色**填充，半透明黑色背景
- 技能条：15×2 px，**紧挨血条正下方**，亮白色填充，半透明黑色背景
- 满值时填充完全盖满背景；干员血条常显（不受控制台"显示植物血量"开关影响），不显示数字

### 1.5 干员唯一性

**每种干员场上最多部署 1 个**（明日方舟规则）：

- 卡片层：场上已有同类型干员时，干员卡片置灰不可点击（`card.gd judge_card_ready` 检查 `OperatorManager.get_operator_count_by_type`）
- 种植层：手持时虚影变透明不可种（`hm_character._update_cell_shadow` 兜底）
- 干员部署/死亡时通过 EventBus `operator_deployed` / `operator_death` 刷新卡片状态（`card_slot_battle` 订阅）

### 1.6 攻击范围与部署方向

**所有干员的攻击范围是有限的格子范围**（非单行直线），参照 Wiki 满级范围：

- 范围形状：`DetectComponentOperator.ATTACK_RANGE_SHAPE`（克洛丝速射手为 3 行 × 4 列，干员在中间行最左列）
- 部署方向：手持干员卡拖到格子上时，**方向 = 鼠标相对格子的位置**（左右/上下四向），并实时显示**攻击范围预览**（半透明白色格子）；点击种植即按当前方向部署
- 检测：`DetectComponentOperator`（继承 `DetectComponent`）每 0.1s 遍历场上僵尸，判断僵尸是否落在（按方向旋转的）范围格内，取最近者为目标，发 `signal_can_attack`
- 攻击：`AttackComponentOperator` 朝目标位置发射直线子弹（跨行 `is_activate_lane=false`）
- 干员本体：`set_attack_direction()` 设置方向并左右翻转形象

### 1.7 点击选择 → 撤退 / 技能

- 选中：`OperatorManager._unhandled_input` 在游戏阶段、**未手持卡片/铲子**时，用物理点查询（`intersect_point`，植物受击检测层 layer 2）找鼠标下的干员 → 弹出干员菜单
- 干员菜单：`scenes/operator/operator_menu.tscn`（CanvasLayer），显示干员名 + [技能][撤退] 按钮，点菜单外空白关闭
- 撤退：`Operator000Base.retreat()` → 返还 `部署费用 × operator_retreat_refund_ratio`（向下取整）→ 复用 `be_shovel_kill()` 移除（不触发亡语、释放格子、不重置卡片冷却，与铲子一致）
- 技能按钮：`use_skill()` 失败（SP 未满）时播放 buzzer 音效
- 召唤物（`Summon000Base`）默认禁用撤退与手动技能（按钮置灰）

## 2. 动画约定与 Spine 管线

### 2.1 动画命名约定（必须遵守）

干员使用 `AnimComponentOperator`（`scripts/character/components/anim_component/component_anim_operator.gd`，基于 AnimationPlayer），固定动画名：

| 动画名 | 用途 | 触发 |
|---|---|---|
| `idle` | 待机（循环） | 入场动画结束后、攻击结束 |
| `attack` | 攻击 | `AttackComponentOperator` 每轮发射后 |
| `skill` | 技能释放 | `use_skill()` 成功 |
| `die` | 死亡 | 死亡流程（淡出后移除） |

动画轨道一律作用于 `Body/BodyCorrect/OperatorSprite` 容器（`OperatorSprite` 为干员身体容器，实际美术精灵放在其下），这样无论内部精灵如何替换，动画保持生效。缺动画名时容错跳过。

- **入场动画**：完全由 Spine `Start`→`Idle` 承担（`Operator000Base.play_enter_animation()`，无 tween 淡入升起等旧占位动画）
- **死亡动画**：`character_death()` 有 Spine 形象时播 `Die`（1.0s）等 1.1s 后移除；无 Spine 时直接移除（占位动画已移除）
- **注意**：干员场景里的 `AnimationTree` 只是为满足攻击组件基类的 `$"../AnimationTree"` 引用而存在，**必须显式 `active = false`**（其默认 active 会把 BlendTree 输出持续应用，将 `OperatorSprite.modulate` 重置为 0 导致形象透明）；占位动画轨道 `update` 用 0（continuous 插值），否则动画值不插值

### 2.2 素材情况

明日方舟角色素材为 **Spine 3.8.99 骨骼动画**（`.skel` 二进制 + `.atlas` + `.png`），来自游戏客户端提取（详见根 `AGENTS.md` §10 素材管线）。项目 `bin/` 内置**自编译 spine-godot GDExtension（Spine Runtime 3.8）**，可**直接加载游戏原始 3.8.99 数据（含加密头），无需版本转换**。

克洛丝素材在 `assets/image/operator/kroos/`：`char_124_kroos.skel/.atlas/.png`（战斗模型，动画 `Idle/Attack/Start/Die/Default`）；`build_*` 为基建模型（动画 `Relax` 等，暂未用）。

### 2.3 Spine 接入（已实现，克洛丝已验证）

**形象节点**：干员场景在 `Body/BodyCorrect/OperatorSprite` 下挂 `OperatorSpineSprite`（`scripts/character/operator/operator_spine_sprite.gd`，`extends SpineSprite`），用 `@export skel_path/atlas_path` 在 `_ready` 时**运行时加载**数据（不依赖编辑器导入状态）。

**播放驱动**：`Operator000Base.get_operator_spine()` 遍历 OperatorSprite 容器找 SpineSprite；`AnimComponentOperator` 有 Spine 时驱动 Spine、无则回退 AnimationPlayer 占位动画（接口 `play_idle/play_attack/play_skill/play_die` 不变）。

动画映射：

| 逻辑动画 | Spine 动画 | 说明 |
|---|---|---|
| `idle` | `Idle` | 循环待机（2.0s） |
| `attack` | `Attack` → `Idle` | 单次攻击（0.93s），`add_animation` 自动衔接 Idle |
| 入场 | `Start` → `Idle` | `play_enter_animation()` 淡入升起后播放（0.83s） |
| `die` | `Die` | 死亡动画（1.0s） |
| `skill` | 无 | 战斗模型无技能动画，保留 AnimationPlayer 缩放提示 |

**关键约定**：`OperatorSpineSprite._ready` **只加载数据、不自动播放**——部署预览（`HM_Character` 复制 OperatorSprite 子树）需要**静态形象**；播放由 `ready_norm → play_enter_animation` 驱动。

**3.8 移植版 API 注意**（运行时实测）：`set_animation(name, loop, track)`；`add_animation(name, delay, loop, track)`（**delay 在第 2 参**）；请求不存在的动画名**静默保持当前轨道**；`get_current(track).get_animation().get_duration()` 可取时长。更多坑见 `docs/开发相关.md` "Spine 接入踩坑"。

## 3. 克洛丝（Kroos）

### 3.1 数据（按 Wiki 精英1满级，可调）

| 项 | 值 | 说明 |
|---|---|---|
| 部署费用 | 10 DP | `SunCost` 字段复用为部署费用 |
| 再部署时间 | 70 s | `CoolTime` 字段 |
| HP | 1060 | 场景 `HpComponent.max_hp`（精英1满级） |
| 攻击力 | 375 | 子弹 `bullet_101_kroos_arrow` 的 `attack_value` |
| 攻击间隔 | 1.0 s | `AttackComponent.attack_cd` |
| 攻击范围 | 3 行 × 4 列 | 干员在中间行最左列（速射手精英1范围） |
| 攻击方式 | 范围内朝目标发射箭矢 | 直线跨行子弹，速度 900（豌豆的 3 倍） |
| 特性 | 速射手 | `can_attack_zombie_status=9`（可攻击空中） |

> 注：明日方舟的防御/法术抗性在 PVZ 数值体系中没有对应，暂不参与伤害计算（可后续加物理减伤）。

### 3.2 箭矢子弹

`bullet_101_kroos_arrow`：**自绘"光之箭"样式**（`ArrowVisual`）：细白光针（14px 长、约 1px 宽，白色发光）+ 前端深色小三角箭头 + 尾部白色拖尾（流星残影，向后渐隐），无实体箭杆/箭羽；速度 900（豌豆 300 的 3 倍），跨行直线飞行，命中后消失。

**发射时机与发射点**：`bullet_spawn_delay = 0.55`（先播 Spine `Attack` 动画，延迟到动画中"松手"时刻再发射）、`bullet_spawn_offset = Vector2(80, -69)`（箭矢从弩口发出）。**校准数据存 `data/operator_calibration.json`**：`_shared` 段为全干员共用配置（容器Y/Spine位置/缩放，可调），其余键为干员 id（`operator_id`），存该干员独有的 delay+spawn。游戏运行时 `OperatorCalibration` 按 `operator_id` 读取并应用（部署与部署预览都生效）。校准用调试工具 `test/operator_debug_tool.tscn`：干员下拉切换（自动扫描素材文件夹），点击画面直接设发射点，自动循环射箭，「应用」写入 JSON。

### 3.3 天赋 要害瞄准·初级

`operator_001_kroos.gd`：攻击时 `crit_chance = 0.2`（精英1满级 20%）概率当次攻击伤害 `× crit_multiplier = 1.5`。实现于 `get_attack_paras()` 钩子（`AttackComponentOperator` 发射前调用）。

### 3.4 技能 二连射·自动（攻击回复·自动触发）

- SP 上限 5，每次攻击回复 1 点（攻击回复）
- SP 满后自动触发（`is_auto_trigger = true`），也可点菜单 [技能] 手动触发
- 触发后**下次攻击连续射击 2 发**（每发 100% 攻击力），SP 清零重新积攒

### 3.5 部署预览

- **两段部署**：**第一段（手持/定位）**：方向固定为右，虚影所在格可种植时即显示**朝右的攻击范围预览**，且**隐藏鼠标上的干员形象**（只显示地面虚影，避免重叠；只针对干员，植物仍同时显示鼠标形象+地面虚影）；点击格子确定位置（**不创建干员**，只把预览虚影固定到目标格）进入方向选择阶段；**第二段**按鼠标朝向实时确定方向（范围预览跟随，虚影朝向跟随），点击确认才**真正创建干员并播放上场动画**（`ready_norm` → Spine `Start` → `Idle`，扣部署点）、右键取消（未创建，不扣部署点）。**预览虚影不透明度 100%**，且播放 Spine `Idle` 待机动画（非静态帧）
- **范围预览**：`OperatorRangePreview` 按**真实草坪格子节点**生成范围（与草坪完全对齐，越界格跳过；范围含干员所在格——`ATTACK_RANGE_SHAPE` 含 `(0,0)` 即显示，特殊干员形状中不含则不显示），每格矩形边长 = **网格间距 + 3px 重叠**（相邻格子间若有空隙，各向对方延伸半个空隙 = 无缝覆盖；重叠消除 Polygon2D 光栅化细缝，右/上方向都有）；**角相邻（斜对角）的格子对在共享角点插入直角桥接方块**（`BRIDGE=6`），缺口补上且轮廓全部为 90° 直角（无 45° 斜边、无圆角、**无边框**）；条纹为 **shader 45° 橙/透明斜纹**（`shaders/operator_range_stripes.gdshader`，参考 spatial 版算法：世界坐标投影到条纹方向 + `mod` + `count=5` 条累加 + `smoothstep` 软边；`width=16.5px`、`spacing=165px` = `count × 2 × width`，**条纹宽与间隔等距**；`base_color` 淡橙底 alpha 0.10 盖住草坪网格线）白色小箭头与提示文字
- **转身/正背面**（`operator_000_base.gd` + `DetectComponentOperator` 驱动）：干员默认正面素材（BattleFront），`OperatorSpineSprite` 同时加载背面素材（`back_skel_path/back_atlas_path`，BattleBack，方舟战斗中干员背对镜头视角）；**只有朝上（Up）部署时默认背面**（`is_default_back_direction`），入场显示背面且**素材一直保持背面**（`reset_visual` 恢复到默认素材，朝上部署入场后不攻击也不切正面）；**有攻击目标时**：目标在干员**上方行**（`lane < 干员行`）→ `set_back_visual(true)` 切背面素材 + `scale.x` 取反（转身），目标在下方行/同排 → 正面素材（背面反之）；**目标在反向列**（干员背后方向但仍需在攻击范围内，`behind_turn_cols=0.4` 格）→ `set_behind_visual(true)` 只 `scale.x` 反转不切换素材；无目标 → `reset_visual()` 恢复默认。转身带**动画**（scale.x→0 变薄 → 归零切素材 → 恢复目标 scale，`TURN_ANIM_TIME`）。**预览虚影**按方向切素材（方向选择阶段鼠标移到朝上=后时虚影也切背面素材，`hm_character._update_shadow_back_visual`）。素材切换保持当前动画（`switch_data` 重播缓存动画名；正/背数据懒加载支持复制节点）
- **干员菜单攻击范围小图标**：`OperatorMenuRangeIcon` 网格图，点亮范围内格（橙黄），干员格白点标记
- 手持/虚影：**Spine 战斗形象静态帧**（干员场景 `Body/BodyCorrect/OperatorSprite` 复制，含 `OperatorSpineSprite`；只加载数据不播放动画），与部署后一致、大小合适（非卡片立绘）
- **再部署 CD**：部署时不开始冷却，撤退/死亡后才按卡片 `cool_time` 开始计（取消部署不触发冷却）

## 4. 维什戴尔（Wisadel）计划

## 5. 新增干员步骤（速查）

1. `CharacterRegistry.PlantType` 加枚举（P052 起），`OperatorPlantType` 加入类型
2. `PlantInfo` 登记：`PlantName / CoolTime(再部署) / SunCost(部署费用) / PlantConditionResource / PlantScenes`
3. 从 `operator_000_base.tscn` 新建继承场景 + 脚本 `extends Operator000Base`，设置 `plant_type`

5. 重写 `get_attack_paras()`（连射/倍率）与 `_on_skill_use()`（技能效果）
6. **Spine 素材接入 + 校准**（新增干员必做）：
   - 素材放 `assets/image/operator/<id>/`（skel/atlas/png），场景里挂 `OperatorSpineSprite` 填路径；**场景根节点设置 `operator_id = "<id>"`**（素材文件夹名, 同时是校准 JSON 的键）
   - 运行 `test/operator_debug_tool.tscn`：下拉选新干员 → 点击画面把发射点对准弩口/松手位置 → 拖延迟/发射点 → 点**「应用」**写入 `data/operator_calibration.json`（游戏运行时读取覆盖场景默认值；不写场景文件）
   - 位置/缩放为全干员共用配置（JSON `_shared` 段），在调试工具"共用配置"滑块区调整，一般无需逐干员改
   - 调试工具自动扫描素材文件夹（排除 `build_` 基建与 `mini.skel`）；新干员在工具脚本登记 `OPERATOR_NAMES`（显示名）与 `OPERATOR_GAME_VALUES`（初始值回退）
7. `AllCards` 加卡片（`card_plant_type` + `is_operator_card = true`）
8. `Global.global_game_state.curr_operator` 加入白名单
