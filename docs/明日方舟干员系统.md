# 明日方舟干员系统

本文档介绍《植物大战僵尸 × 明日方舟》同人中的干员系统：架构、实现约定、动画管线、克洛丝数值与后续计划（维什戴尔等）。

## 1. 总体设计

### 1.1 干员 = PlantType 子集

干员**注册为 `CharacterRegistry.PlantType` 枚举**（P050 起，见 `scripts/autoload/global/character_registry.gd`），场景继承完整植物管线：

```
Character000Base
└── Plant000Base          (scenes/character/plant/plant_000_base.tscn)
    └── Operator000Base   (scenes/character/operator/operator_000_base.tscn)
        └── Summon000Base (scenes/character/operator/summon_000_base.tscn)
```

这样干员天然获得：卡片→手持→种植→植物格子（`PlantCell`）→被僵尸啃食→行渲染/斜面等全部能力，**与植物友方**（同一受击检测层、植物子弹不会误伤）。

- 干员类型列表：`CharacterRegistry.OperatorPlantType`，判断函数 `CharacterRegistry.is_operator_type(plant_type)`
- 干员卡片标记：`CardBase.is_operator_card`（消耗**部署点数**而非阳光）
- 可选干员白名单：`Global.global_game_state.curr_operator`（决定选卡界面干员页显示哪些）

### 1.2 部署点数（DP）

与明日方舟一致，干员消耗独立的**部署点数**，随时间自动回复，不消耗阳光：

- 管理器：`OperatorManager`（`scripts/manager/operator_manager/operator_manager.gd`，挂在主游戏 `Manager` 节点下）
- 关卡参数（`ResourceLevelData`，默认值）：
  - `is_can_use_operator = true`：本关卡是否允许干员
  - `operator_start_deploy_point = 10`：初始部署点数
  - `operator_max_deploy_point = 99`：上限
  - `operator_regen_interval = 2.0`：回复间隔（秒，≤0 不回复）
  - `operator_retreat_refund_ratio = 0.7`：撤退返还比例
- 变更广播：`EventBus.push_event("update_deploy_point", [value])`，出战卡槽（`CardSlotBattle`）订阅后更新右上角 DP 数字并刷新干员卡片可点击状态
- 测试模式（`main_game.is_test`）初始 DP 直接满额，便于调试

### 1.3 技能系统（SkillComponent）

`scripts/character/components/skill_component/component_skill.gd`，挂在干员头顶（HP 条上方），常显：

- `max_sp`：技能条上限（技能消耗）
- 回复方式 `E_SpRecoveryType`：`Attack`（攻击回复，每次攻击 +`sp_gain_per_attack`）/ `Time`（时间回复）/ `None`
- `is_auto_trigger`：就绪后是否自动触发
- 信号：`signal_skill_ready` / `signal_skill_use` / `signal_sp_change`

技能触发流程：`Operator000Base.use_skill()` → `SkillComponent.use_skill()` → 播放 `skill` 动画 → 调用虚钩子 `_on_skill_use()`（子类重写实现技能效果）。

### 1.4 血条与技能条（明日方舟风格）

干员的血条/技能条与植物僵尸不同，为头顶**迷你条**：

- 血条：15×2 px，**蓝色**填充，半透明黑色背景
- 技能条：15×2 px，**紧挨血条正下方**，亮白色填充，半透明黑色背景
- 满值时填充完全盖满背景；干员血条常显（不受控制台"显示植物血量"开关影响），不显示数字

### 1.5 干员唯一性

**每种干员场上最多部署 1 个**（明日方舟规则）：

- 卡片层：场上已有同类型干员时，干员卡片置灰不可点击（`card.gd judge_card_ready` 检查 `OperatorManager.get_operator_count_by_type`）
- 种植层：手持时虚影变透明不可种（`hm_character._update_cell_shadow` 兜底）
- 干员部署/死亡时通过 EventBus `operator_deployed` / `operator_death` 刷新卡片状态（`card_slot_battle` 订阅）

### 1.6 攻击范围与部署方向

**所有干员的攻击范围是有限的格子范围**（非单行直线），参照 Wiki 满级范围：

- 范围形状：`DetectComponentOperator.ATTACK_RANGE_SHAPE`（克洛丝速射手为 3 行 × 4 列，干员在中间行最左列）
- 部署方向：手持干员卡拖到格子上时，**方向 = 鼠标相对格子的位置**（左右/上下四向），并实时显示**攻击范围预览**（半透明白色格子）；点击种植即按当前方向部署
- 检测：`DetectComponentOperator`（继承 `DetectComponent`）每 0.1s 遍历场上僵尸，判断僵尸是否落在（按方向旋转的）范围格内，取最近者为目标，发 `signal_can_attack`
- 攻击：`AttackComponentOperator` 朝目标位置发射直线子弹（跨行 `is_activate_lane=false`）
- 干员本体：`set_attack_direction()` 设置方向并左右翻转形象

### 1.7 点击选择 → 撤退 / 技能

- 选中：`OperatorManager._unhandled_input` 在游戏阶段、**未手持卡片/铲子**时，用物理点查询（`intersect_point`，植物受击检测层 layer 2）找鼠标下的干员 → 弹出干员菜单
- 干员菜单：`scenes/operator/operator_menu.tscn`（CanvasLayer），显示干员名 + [技能][撤退] 按钮，点菜单外空白关闭
- 撤退：`Operator000Base.retreat()` → 返还 `部署费用 × operator_retreat_refund_ratio`（向下取整）→ 复用 `be_shovel_kill()` 移除（不触发亡语、释放格子、不重置卡片冷却，与铲子一致）
- 技能按钮：`use_skill()` 失败（SP 未满）时播放 buzzer 音效
- 召唤物（`Summon000Base`）默认禁用撤退与手动技能（按钮置灰）

## 2. 动画约定与 Spine 管线

### 2.1 动画命名约定（必须遵守）

干员使用 `AnimComponentOperator`（`scripts/character/components/anim_component/component_anim_operator.gd`，基于 AnimationPlayer），固定动画名：

| 动画名 | 用途 | 触发 |
|---|---|---|
| `idle` | 待机（循环） | 入场动画结束后、攻击结束 |
| `attack` | 攻击 | `AttackComponentOperator` 每轮发射后 |
| `skill` | 技能释放 | `use_skill()` 成功 |
| `die` | 死亡 | 死亡流程（淡出后移除） |

动画轨道一律作用于 `Body/BodyCorrect/OperatorSprite` 容器（`OperatorSprite` 为干员身体容器，实际美术精灵放在其下），这样无论内部精灵如何替换，动画保持生效。缺动画名时容错跳过。

- **入场动画**：部署时从下方升起 + 淡入（`Operator000Base.play_enter_animation()`，tween 实现，`await tween.finished` 后接 `idle`）
- **死亡动画**：`character_death()` 播放 `die`（淡出）0.6s 后移除
- **注意**：干员场景里的 `AnimationTree` 只是为满足攻击组件基类的 `$"../AnimationTree"` 引用而存在，**必须显式 `active = false`**（其默认 active 会把 BlendTree 输出持续应用，将 `OperatorSprite.modulate` 重置为 0 导致形象透明）；占位动画轨道 `update` 用 0（continuous 插值），否则动画值不插值

### 2.2 素材情况

明日方舟角色素材为 **Spine 3.8.99 骨骼动画**（`.skel` 二进制 + `.atlas` + `.png`），Godot 无法直接导入。当前使用**立绘静态图占位**（`assets/image/operator/kroos/kroos_placeholder.png`，来自 `E:\ark_chararts`），配合占位关键帧动画演示管线。

### 2.3 接入官方 spine-godot 插件（后续步骤）

1. 从 [esotericsoftware/spine-runtimes](https://github.com/EsotericSoftware/spine-runtimes) 获取与项目 Godot 4.6.2 匹配的 **spine-godot GDExtension** 预编译版本（官方文档：https://en.esotericsoftware.com/spine-godot；GitHub Actions `spine-godot-extension-v4-all.yml` 可构建各 Godot 4.x 版本）
2. 将插件目录放入 `addons/`，在 `project.godot` 启用
3. 将角色素材（`.skel/.atlas/.png` 三个文件）放入 `assets/image/operator/<角色>/`，用 spine-godot 的 `SpineSprite`/`SpineAnimationState` 节点播放
4. 保持 `AnimComponentOperator` 接口不变：在 `play_anim(name)` 内改为驱动 Spine 状态机（动画名映射到 Spine 动画名，如 `idle → "Idle"`、`attack → "Attack"`）
5. 卡面 `CharacterStatic` 同样可替换为 Spine 预览节点

## 3. 克洛丝（Kroos）

### 3.1 数据（按 Wiki 精英1满级，可调）

| 项 | 值 | 说明 |
|---|---|---|
| 部署费用 | 10 DP | `SunCost` 字段复用为部署费用 |
| 再部署时间 | 70 s | `CoolTime` 字段 |
| HP | 1060 | 场景 `HpComponent.max_hp`（精英1满级） |
| 攻击力 | 375 | 子弹 `bullet_101_kroos_arrow` 的 `attack_value` |
| 攻击间隔 | 1.0 s | `AttackComponent.attack_cd` |
| 攻击范围 | 3 行 × 4 列 | 干员在中间行最左列（速射手精英1范围） |
| 攻击方式 | 范围内朝目标发射箭矢 | 直线跨行子弹，速度 900（豌豆的 3 倍） |
| 特性 | 速射手 | `can_attack_zombie_status=9`（可攻击空中） |

> 注：明日方舟的防御/法术抗性在 PVZ 数值体系中没有对应，暂不参与伤害计算（可后续加物理减伤）。

### 3.2 箭矢子弹

`bullet_101_kroos_arrow`：**自绘杏仁状箭矢**（`ArrowVisual`，长 8px、最宽 2px、两端尖端过渡），带微弱发光（半透明外层 + 亮芯），无需贴图资源；速度 900（豌豆 300 的 3 倍），跨行直线飞行，命中后消失。

### 3.3 天赋 要害瞄准·初级

`operator_001_kroos.gd`：攻击时 `crit_chance = 0.2`（精英1满级 20%）概率当次攻击伤害 `× crit_multiplier = 1.5`。实现于 `get_attack_paras()` 钩子（`AttackComponentOperator` 发射前调用）。

### 3.4 技能 二连射·自动（攻击回复·自动触发）

- SP 上限 5，每次攻击回复 1 点（攻击回复）
- SP 满后自动触发（`is_auto_trigger = true`），也可点菜单 [技能] 手动触发
- 触发后**下次攻击连续射击 2 发**（每发 100% 攻击力），SP 清零重新积攒

### 3.5 部署预览

- 手持/虚影：**战斗形象**（干员场景 `Body/BodyCorrect/OperatorSprite` 复制），与部署后一致，大小合适（非卡片立绘）
- 攻击范围预览：虚影在格子上时显示半透明白色范围格，随部署方向实时更新
- 卡片立绘（选卡界面）：保留小尺寸立绘

### 3.6 相关文件

- 脚本：`scripts/character/operator/operator_001_kroos.gd`
- 场景：`scenes/character/operator/operator_001_kroos.tscn`
- 子弹：`scenes/bullet/bullet_101_kroos_arrow.tscn`（占位贴图为豌豆，后续替换箭矢）
- 卡片：`scenes/autoload/all_cards.tscn` → `PlantCards2/Card5`

## 4. 维什戴尔（Wisadel）计划

- 枚举已预留：`PlantType.P051Wisadel`（**暂不登记 PlantInfo**，避免解析不存在场景报错）

- 接入时：素材放 `assets/image/operator/wisdel/`（`E:\ark_chararts\char_1035_wisdel`），实现范围攻击（可参考抛物线子弹或加农炮子弹体系），完成后在 `PlantInfo` 登记并加入 `curr_operator` 白名单

## 5. 新增干员步骤（速查）

1. `CharacterRegistry.PlantType` 加枚举（P052 起），`OperatorPlantType` 加入类型
2. `PlantInfo` 登记：`PlantName / CoolTime(再部署) / SunCost(部署费用) / PlantConditionResource / PlantScenes`
3. 从 `operator_000_base.tscn` 新建继承场景 + 脚本 `extends Operator000Base`，设置 `plant_type`
4. 按 §2.1 提供 `idle/attack/skill/die` 动画；攻击用 `AttackComponentOperator` + `DetectComponentOperator`（配置 `attack_cd`、`attack_bullet_type`、范围形状若不同则改 `ATTACK_RANGE_SHAPE`）
5. 重写 `get_attack_paras()`（连射/倍率）与 `_on_skill_use()`（技能效果）
6. `AllCards` 加卡片（`card_plant_type` + `is_operator_card = true`）
7. `Global.global_game_state.curr_operator` 加入白名单

## 6. 已知取舍（欢迎调整）

- 撤退**不重置**卡片冷却（与铲子一致）；完整的"再部署时间重置"留待后续
- 部署点数数值（初始 10 / 上限 99 / 2s 回复 1 点）为初版平衡，可在关卡参数或注册表中调整
- 攻击范围形状固定为克洛丝速射手的 3×4（`ATTACK_RANGE_SHAPE` 常量），后续干员（如维什戴尔的投掷手范围）需按职业调整或做成每干员配置
- 部署方向为 4 向，通过"鼠标相对格子的位置"选择；上/下方向在 PVZ 横向战场中实际作用有限
- 干员存档目前跟随植物存档流程（`get_save_game_data_plant`），技能点/部署点数不进存档
