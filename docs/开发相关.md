# 项目目录说明
该部分解释说明本项目主体目录(二级目录未完全列出)
- addons:插件目录,主要使用RGa_PVZ和anim_player_refactor插件处理动画
- animation:动画目录,保存所有动画文件,大部分动画都是单独保存为tres格式文件,少部分保存在场景文件中
- assets: 资产文件夹,包含图片素材 音乐音效素材等,考虑到版权问题,<mark>github中将该目录删除,加群或者从大版本更新视频简介获取完整项目内容</mark>
- data: 主要保存Theme主题资源 和 数据文件(图鉴数据)
- docs: 文档目录,保存项目说明文档（如 [子弹说明文档](子弹说明文档.md)）
- readme_show: readme展示的相关图片资源
- resources: 资源文件夹
- - character_resouce: 角色相关资源文件夹:body掉血变化\植物种植条件 <mark>(植物种植条件资源必须保存在该目录下)</mark>
- - crazy_dave_resource: 戴夫对话资源
- - <mark>level_date_resource: 游戏关卡设置相关的资源文件</mark>
- scenes:场景文件
- scripts: 脚本文件
- - autoload: 自动加载的全局脚本文件
- - bullet: 子弹脚本文件
- - character: 角色脚本文件(僵尸\植物\组件)
- - resources: 自定义资源脚本文件(关卡\植物种植条件\戴夫对话\body变化)
- shaders: 着色器脚本文件
- shader_material: 材质文件,保存僵尸出土时材质设置

# 植物僵尸动画
使用[R2Ga_PVZ](#r2ga_pvz)将植物大战僵尸的动画文件转换为Godot游戏引擎所支持的动画格式。

僵尸动画：
- 使用插件[anim_player_refactor](#anim_player_refactor)删除一些轨道，主要是删除删除僵尸胳膊和头相关的visible轨道，僵尸掉手或掉头时使用代码控制visible。
- 或者将需要使用代码隐藏的节点用一个新的Node2D节点作为其父节点，代码控制其显示与隐藏，不用修改动画文件（推荐）

植物动画：
- 植物射击时眨眼和idle时眨眼节点不同，由于射击时眨眼动画需要使用visible轨道，使用插件[anim_player_refactor](#anim_player_refactor)将idle时的眨眼节点visible轨道删除，使用代码控制植物眨眼。

## 子弹类型
子弹分为4类: 直线\抛物线\追踪子弹\ 其他（加农炮）
### 直线
直线型 非穿透性攻击 子弹在碰撞到屋顶斜坡时判断是否破碎

### 抛物线
抛物线子弹使用贝塞尔曲线控制子弹弹道,根据目标僵尸位置确定终点位置,可以跟随僵尸移动,僵尸移动超出一定限制,固定最终落点

### 追踪子弹
追踪子弹根据贝塞尔曲线每帧更新移动方向

### 加农炮子弹
加农炮子弹继承Node2D节点,与子弹基类无继承关系

# 碰撞相关

## 碰撞检测

### 斜面地图
角色受击碰撞箱分为两类: 检测受击碰撞箱和真实受击碰撞箱
非斜面(屋顶)地图:检测受击碰撞箱和真实受击碰撞箱重合
斜面(屋顶)地图:
- 定义两个层面: 真实层面 & 检测层面  (两个层面的位置在斜面上有不同)
- - 检测层面: 检测层面,为一个水平线,每一行的水平面,直线,受击检测框,攻击检测框,处于该层面,在斜面时,角色本体(根节点)根据斜面移动,检测层面所在组件移动回原始位置， 
- - 真实层面: 地图斜面时角色本体(根)所在层面. 在斜面时,角色本体(根节点)根据斜面移动,子弹攻击敌人时,子弹检测真实碰撞箱
爆炸组件中，一般爆炸组件的检测框在检测层面，爆炸特效在真实层面，不移动


除了子弹检测目标\无行属性攻击组件直线子弹植物(杨桃)\小推车检测僵尸时使用真实层面的检测框,其余检测均使用检测层面检测框

### 检测过滤
检测碰撞时会同时检测角色受击状态
  若可以检测者可以检测到目标受击状态,发射可以攻击信号
  若不能攻击,连接僵尸状态改变信号,僵尸状态改变时,重新判断是否可以攻击

植物:
```gd
enum E_BeAttackStatusPlant{
	IsNorm = 1,		## 正常
	IsFloat = 2,	## 悬浮
	IsDown = 4, 	## 地刺
	IsShort = 8, 	## 低矮植物（僵尸方子弹检测过滤 没有做僵尸方直线子弹 未使用）
}
```
僵尸:
```
enum E_BeAttackStatusZombie{
	IsNorm = 1,		## 正常
	IsJump = 2,		## 跳跃
	IsDownPool = 4,		## 水下
	IsSky = 8,			## 空中
	IsDownGround = 16,	## 地下
	IsJumpInPool = 32,	## 跳入泳池,该状态无法被高建国拦截
}
```

## 碰撞层说明
- layer 1 World : 世界层，房子区域\泳池碰撞\屋顶斜坡
- layer 2 PlantHurtBoxDetecttion : 植物层，植物所在层
- layer 3 ZombieHurtBoxDetecttion : 僵尸层，僵尸本体所在层，
- layer 4 BulletFromPlant : 植物子弹所在层，
- layer 5 ZombieHurtBoxDetecttionOnAttack : 僵尸攻击碰撞时受击碰撞箱所在层,不攻击时和本体受击碰撞箱重叠,攻击时向前移动,特殊植物可以检测(倭瓜\大嘴花)
- layer 6 ZombieHurtBoxDetecttionBeHypnotized : 僵尸被魅惑层，被魅惑僵尸改变至该层，植物子弹检测不到，
- layer 7 Bowling : 保龄球子弹层，撑杆跳僵尸可以检测到该层跳跃，
- layer 8 BulletFromZombie : 僵尸子弹区域所在层,无用
- layer 9 PlantHurtBoxReal: 植物真实受击区域
- layer 10 ZombieHurtBoxReal: 僵尸真实受击区域
- layer 11 ZombieHurtBoxRealBeHypnotized: 魅惑僵尸真实受击区域
- layer 12 ItemDetect:道具检测层(梯子、脑子等)
- layer 13 ItemReal: 道具真实层

# 植物种植相关
植物位置有四种: `float(漂浮植物:咖啡豆)、down(底部植物:花盆、睡莲)、norm(正常普通植物：豌豆射手)、shell(壳类植物：南瓜头)`
地形分为6种（植物格子为某一种类型+“无”类型）：`"1 无", "2 草地", "4 花盆", "8 水", "16 睡莲", "32 屋顶/裸地"`

植物种植的地形可以为多种，如豌豆射手：`22 = 2(草地) + 4(花盆)+ 16(睡莲)`
植物的位置属性只能选一种

## 植物种植条件
每个植物的种植条件使用自定义资源（`ResourcePlantCondition`），相同的种植条件可以使用同一个资源
种植条件资源需要保存在`res://resources/plant_resource/plant_condition/`目录下

植物种植条件分为特殊和非特殊,
紫卡植物一般为非特殊植物,
特殊植物需要重写对应资源脚本,重写特殊植物种植条件函数代码
特殊紫卡植物(玉米加农炮)判断是否能种植时,只走特殊植物判定种植函数,不会在走紫卡植物判定函数
双格植物只针对玉米加农炮写了个资源脚本,若扩展需写对应的资源脚本文件

## 植物格子
植物格子（`PlantCell类`）管理当前格子的植物
普通植物种植时需同时满足当前植物格子空闲位置和地形才可以种植
特殊植物需继承种植资源脚本重写判断函数判断是否可以种植

植物格子有每个位置对应的植物容器作为种植植物的父节点
原始PlantCell节点如下：
- PlantCell (PlantCell)
  - PlantDownContainer (Node2d)
  - PlantFloatContainer (Node2d)
  - PlantNormContainer (Node2d)
  - PlantShellContainer (Node2d)

本项目norm和shell位置的植物可以跟随down的植物上下移动（原版花盆种植植物后就不动了，我写完才发现，就这样了）
down位置植物需要容器节点（DownPlantSelfContainer）作为norm和shell位置植物的父节点，down位置植物移动容器节点从而带动norm和shell位置植物移动（使用动画或tween控制移动）
种植down位置植物时将植物格子的norm和shell位置的容器节点作为down位置植物的容器节点的子节点。
down位置植物节点如下：
- DownPlant(Plant)
	- DownPlantSelfContainer(Node2D)
	- DownPlantOtherNode

种植底部植物后如下所示
- PlantCell (PlantCell)
  - PlantDownContainer (Node2d)
	- DownPlant(Plant)
		- DownPlantSelfContainer(Node2D)
			- DownPlantOtherNode
			- PlantShellContainer(Node2d)
			- PlantNormContainer (Node2d)
  - PlantFloatContainer (Node2d)


## 可能踩的坑
- 1、植物需要对应的种植条件资源文件，需要在global脚本中更新对应的PlantInfo
- 2、静态迷雾_ready()函数中会调用init_static_fog()初始化静态迷雾，会删除`
@export var del_fog_postion_area:Vector2 = Vector2(650, 700)`之外的静态迷雾,如果修改屏幕显示大小，需修改该参数适应屏幕

### 场景/脚本踩坑记录（持续补充）
> 约定：开发中踩到并解决的坑，一律记录到本节（或对应的领域文档），避免重复踩。

- 3、**继承场景的 ext_resource 引用基类场景时，uid 必须写对**。`uid` 写错（如把 `character_000_base` 的 uid 当成 `plant_000_base` 的）虽然会"用文本路径回退"不报错，但会导致**继承场景中所有 `%唯一名`（SleepComponent/BlinkComponent 等）解析失败**、脚本 `_ready` 连锁报错。写新继承场景前先 `head -1` 确认基类真实 uid。
- 4、**`plant_000_base.tscn` 用 `type=` 重新声明了 `Body`（parent=SleepComponent）**，这是"睡眠 Zzz 容器"，**角色形象 Body 仍在根节点下**（带 `body_character.gd` 脚本 + `BodyCorrect`）。因此：具体植物场景**必须自己补 `BodyCorrect`**（豌豆等每个场景都有），形象精灵一律挂在 `Body/BodyCorrect` 下（相对根节点的路径，不是 `SleepComponent/Body`）。
- 5、**新增脚本带 `class_name` 后，headless 验证前必须先跑一次 `godot --headless --import`**，否则新 class_name 未注册到全局脚本类缓存，所有引用它的脚本解析报错。
- 6、**自造 `uid://xxx` 会警告并回退**（可接受）；但**不要依赖自造 uid**，编辑器打开后会自动重新分配。
- 7、**`--script xxx.gd` 模式不加载自动加载单例**（`Global/EventBus` 等全局标识符不可用）。headless 集成测试要用"测试场景实例化主游戏场景"的方式（正常 main loop）跑。
- 8、**`Node2D.get_global_mouse_position()` 是 CanvasItem 方法**，普通 `Node`（如子管理器）没有，要用 `main_game.get_global_mouse_position()`。
- 9、**动画轨道 `"update"` 值**：`0`=continuous（插值，豌豆等全部用 0）、`1`=discrete（不插值，动画值跳变/不动）。手写占位动画别用 1。
- 10、**`AnimationTree.active` 默认值为 true**（不是休眠）。仅为满足"攻击组件基类 `$"../AnimationTree"` 引用"而加的占位树，必须显式 `active = false`，否则它每帧把 BlendTree 输出应用到动画属性上（例如把节点 `modulate` 持续重置为 0 → 角色透明只剩血条）。排查"角色不显示"记得先看这条。
- 11、**继承 `DetectComponent` 才能被攻击组件 `detect_component is X` 类型检查**：GDScript 中 `is` 判断要求类型有继承关系，自定义检测组件应 `extends DetectComponent`（复用其信号与属性），不能直接 `extends ComponentNormBase`。
- 12、**检测基准统一用"根位置/行地面"**：僵尸/干员的 `hurt_box` 位置偏上（约 -50px），与范围矩形（以根位置为基准）不匹配会检测不到，用 `global_position` 判断行与距离。

### Spine 接入踩坑（干员，2026-08 记）
- 13、**明日方舟 skel 加密头格式**：`1c + 28 字节随机串 + 07 + "3.8.99"`（无 `\x00` 结束符）。`tools/spine38_probe.py` 按 `\x00` 找版本串结束会失败——**不要按明文 3.8 格式硬解**；项目 `bin/` 的自编译 Spine Runtime 3.8 扩展可**直接加载原始加密 skel**（无需去头/转换），headless 冒烟验证通过。
- 14、**SpineSkeletonDataConverter 转换会丢动画**：转出的 JSON/skel 只有 `Attack/Default/Idle/Start`，**丢了 `Die`**；但原始 skel 运行时实测**存在 `Die`（1.0s）**。**以运行时为准**（`get_current(track).get_animation().get_name()` 探测），不要以转换产物为准。同理动画名清单（Idle 2.0s / Attack 0.93s / Start 0.83s / Die 1.0s）也应以运行时为准。
- 15、**spine-godot 3.8 移植版 API 参数顺序**：`set_animation(name, loop, track)`；`add_animation(name, delay, loop, track)` —— **delay 在第 2 参**（官方 C++ 是 track 在前）；请求**不存在的动画名静默保持当前轨道**（不报错不崩溃，别拿它当存在性检测）；`get_current(track).get_animation().get_duration()` 可取动画时长。
- 16、**headless 可跑通 Spine 纹理加载**：`--headless --script` 模式下 dummy 渲染器不崩溃（此前 spine 4.2 插件在 Godot 4.7.1 上崩溃是插件自身问题，与渲染器无关）。但**编辑器开着时 `--headless --import` 会因扩展 dll 被占用加载失败**（`bin/windows/~libspine...TMP` 锁文件），属环境问题；`--script` 验证不受影响。
- 17、**Spine 形象节点 `_ready` 不要自动播放动画**：部署预览（`HM_Character._create_operator_hand_static` 复制 `OperatorSprite` 子树）需要**静态形象**；若 `_ready` 自动播 Idle 会让手持/虚影也在动。播放统一由 `Operator000Base.ready_norm → play_enter_animation` 驱动（入场 `Start`→`Idle`）。
- 18、**干员模型格内摆放约定**：克洛斯战斗模型骨骼包围盒约 311×431（脚在 y=0、向上延伸，Godot 内 y 翻转后头在上脚在下）。**位置/缩放为全干员共用配置**（JSON `_shared` 段：容器Y=20、Spine=(0,0)、缩放=0.33，运行时 `apply_to` 统一应用，可在调试工具调整）：基类 `operator_000_base.tscn` 的 `OperatorSprite` 容器 `position=(0,20)`（脚部基准），干员场景里的 `OperatorSpineSprite` 放 `(0,0)`。植物根节点在格子底部上方 20px（`PlantNormContainer` anchor bottom、offset -20），脚部比根节点低 20px 与 PVZ 植物一致。每干员独有的 发射延迟+发射点 存 `data/operator_calibration.json` 的干员 id 段，用 `test/operator_debug_tool.tscn` 校准（自动扫描素材文件夹，点击画面设发射点，应用写入 JSON）。
- 19、**僵尸行网格与植物格网格不对齐**：僵尸生成点行距约 101px（166/267/368…），植物格行高 96px（82-178-274…），两套网格逐行累积偏差。干员范围检测若用"像素矩形"判断行方向，向下/向上延伸数行后会漏检（范围格基于干员的植物格网格，僵尸在僵尸行网格上）。**行方向改按僵尸 lane 判断**（`zombie.lane - operator_lane` 是否在覆盖偏移内），x 方向保留像素跨度（见 `component_detect_operator.judge_have_enemy`）。
- 20、**干员两段部署**：**第一段（手持/定位）**方向固定为右，虚影所在格可种植时即显示朝右的范围预览；点击格子仅确定位置（不创建干员，`hm_character.placing_cell`），进入方向选择阶段（`is_operator_dir_selecting`）；第二段鼠标朝向实时决定方向（范围预览跟随、虚影朝向跟随），点击确认才**真正创建干员**（`placing_cell.create_plant` → `ready_norm` 自动播放 Spine 入场 `Start`→`Idle`）并扣部署点，右键取消（未创建，不扣费不冷却）。**预览虚影不透明度 100%** 并播放 Spine `Idle` 动画（`_create_operator_hand_static` 里对副本 `OperatorSpineSprite.play_spine("Idle", true)`）。`hm_character.click_cell` 改为返回 bool（是否结束手持），`hand_manager._on_click_cell` 据此决定是否切回 Null；`_input` 对方向选择阶段单独处理左右键。**注意**：方向选择阶段 `mouse_enter/exit` 不能再更新/隐藏虚影（虚影已固定到目标格），要在函数开头直接 return；第一段创建的 `OperatorRangePreview` 与第二段**复用**（`_create_operator_range_preview` 判空），避免重复节点。
- 21、**攻击范围预览与草坪对齐**：范围格子中心直接取真实植物格节点（`DetectComponentOperator.get_range_cells_on_grid`：`row_col + rotate_offset(偏移, 方向)` 定位，越界格跳过，检测/预览共用同一逻辑），矩形边长 = **网格间距**（相邻格中心距，探测自干员所在格的相邻格）——相邻格间若有空隙，各向对方延伸半个空隙即无缝；**矩形边长再加 3px 重叠** + **合并后顶点清理**（`_clean_polygon`：对齐 0.5px + 删共线点）消除 Polygon2D 光栅化细缝（右向=竖缝、上向=横缝，同一套处理覆盖所有方向）；shader 加**淡橙底色**（`base_color` alpha 0.10），让透明条纹段不露出草坪网格线（缝隙感根源）。检测的 x 边界 = 格子中心 ± 半个网格间距（与预览矩形边界一致）；曾尝试再扩展僵尸受击盒半宽（CapsuleShape2D.radius）让"身体碰到边缘即打"，用户体感未达成，已回滚。**角相邻（斜对角）格子对在共享角点插入直角桥接方块**（`BRIDGE=6`）——比"整体膨胀矩形"好：膨胀会让斜对角连接处产生 45° 斜边，桥接方块则保持轮廓全部 90° 直角。条纹用 shader（`shaders/operator_range_stripes.gdshader`）画 45° 橙/透明斜纹，参考 spatial 版算法（世界坐标投影 + `mod` + `count` 条累加 + `smoothstep` 软边），**条纹宽与间隔等距**（`width=16.5`、`spacing=count×2×width=165`）。
- 22、**明日方舟素材提取注意（正/背面战斗模型）**：`char_124_kroos.ab` 内其实有**两个战斗模型**——`BattleBack`（干员背对镜头，方舟战斗实际视角）和 `BattleFront`（正面），分别对应不同的 skel 资源；旧 `extract_ab.py` 只按文件名提取（两个 `char_124_kroos.skel` 同名互相覆盖，只留正面）。**用 ArkUnpacker**（`tools/ArkUnpacker-v5.1.0.exe`，`-m ab -i <ab> -o <out> --spine --image --text`，按 ab 自动分组 `BattleBack/BattleFront/Building`）才能完整解出。战斗模型 alpha 分离（`<名>[alpha]`），需 `merge_alpha.py` 合成；背面素材在 `assets/image/operator/kroos/back/`（atlas 引用名仍为 `char_124_kroos.png`，放独立子目录避免覆盖）。
- 23、**干员转身/正背面切换**：`OperatorSpineSprite` 加载正（BattleFront）/背（BattleBack）两套数据（`back_skel_path/back_atlas_path`），`switch_data(use_back)` 切换并重播缓存动画（`_last_anim_name`，不能用 `get_current_anim_name` 取——切换瞬间 state 失效返回空会致动画停住，就是"转回去后动画不动"的根因）；**只有朝上（Up）部署方向默认背面素材**（`is_default_back_direction`，用户确认"后"=朝上），部署时切素材后重播入场动画让入场也显示背面，且默认背面时素材**一直保持背面**（`reset_visual` 恢复到默认素材而非固定正面，否则"朝上部署刚落地就转回身"）。**转身/正背面由 `Operator000Base.update_visual_for_target(target)` 统一驱动**（`DetectComponentOperator._update_operator_visual` 每 0.1s 调用，只按攻击目标，范围外敌人不影响）：素材 = 目标在干员**上方行** → 背面、**下方行** → 正面（背面反之）、**同排 → 保持当前素材**（否则僵尸移到左侧同排会把背面切回正面，出现"背面状态僵尸在左侧 scale 没变化"）；**scale 只由目标左右决定（实测关键：正面/背面素材原始都面朝右，素材只决定"视角"不决定朝向）**——目标在右侧 → +1、左侧 → -1（曾误认为背面素材面朝左，按"左右×素材"算导致背面状态 scale 正负反了）。**左右判定带滞回**（`TURN_FLIP_HYSTERESIS=12px`，僵尸 x 在干员 x ± 带内保持上次朝向）——否则僵尸 x 在干员 x 附近抖动时 scale 在 ±1 间反复翻转，出现"左右抽搐"。`_apply_visual` 素材/scale 没变则跳过（防重），变化走**转身动画**（`_play_turn_animation`：scale.x→0 变薄 → 归零时 `switch_data` 切素材 → scale→目标，Tween 驱动，新转身 kill 旧 tween 防抖）。**关键坑：`_apply_visual` 防重必须用"期望状态"（`_target_back`/`_target_scale`）而不是"当前 scale"**——转身动画 0.16s 长、检测每 0.1s 调用，动画中当前 scale 是中间值不等于目标，用当前值判断会每 0.1s kill 重播，动画永远到不了目标 scale（表现为"背面状态僵尸在左侧 scale 没变化"和"僵尸在右侧左右抽搐"），这是转身问题的真正根因；`set_attack_direction` 部署后要同步 `_target_back`/`_target_scale` 避免首次检测误触发。**预览虚影也要按方向切素材**（`hm_character._update_shadow_back_visual`，方向选择阶段鼠标移到朝上=后时虚影切背面素材）；`switch_data` 正/背数据都**懒加载**（`_front_data/_back_data` 为 null 时按路径加载），否则复制出的虚影节点切不回正面。**子弹发射点要随转身镜像**：`shoot_arrow_at_target` 里 `bullet_spawn_offset.x` 按 `OperatorSprite.scale.x` 符号取正/负，否则转身后箭从错误位置射出。
- 21、**干员再部署 CD**：部署时不开始冷却（`card_slot_battle.card_use_end` 对干员跳过 `card_cool`，仅扣部署点）；撤退（`operator_retreat` 事件）或死亡（`operator_death`）后才按卡片 `cool_time` 开始冷却。取消部署必须走 `Operator000Base.cancel_placement`（静默移除、不触发死亡事件，否则会误开始 70s 冷却）。

- - 在每次动画结束时发射animation_finished信号设置停止移动,下一个动画若为移动动画且有过度时间,第一次移动动画会停止移动

- - 若切换动画前后都有移动，动画切换时会快速移动一次，解决办法为设置动画切换间隔时停止移动（扶梯僵尸扶梯掉落）

# 角色（植物和僵尸）
角色（植物和僵尸）根节点只处理基础属性、动画、body相关以及部分特殊角色功能(简单\与角色本体高度耦合不好拆分的)(土豆类准备\大嘴花攻击\魅惑)，其余全都由组件(攻击\攻击检测\移动\睡眠等基础组件)完成
信号连接必须要在角色本体中连接,除非为依赖组件(攻击行为组件与攻击检测组件)


**角色`_ready()`函数中固定根据初始化类型不同进行不同的初始化，继承的植物和僵尸不重写`_ready()`函数，而是重写`init_norm()`函数进行初始化**

角色在`add_child()`添加到节点树之前,使用init_*()函数对角色相关参数(行\初始化类型等)赋值
创建僵尸统一使用ZombieManager的create_norm_zombie()函数创建
部分主游戏全局使用的数据(植物格子\僵尸行等)放在自动加载单例MainGameDate中,每次加载主游戏场景时由对应子管理器更新赋值


## 组件信号连接
为避免信号漫天飞的情况，规定角色及其组件信号连接必需遵循以下规则（角色类的信号）：
- 角色类本身的Timer节点的timeout信号可以在编辑器中直接连接信号，组件自身的Timer信号必须连接至该组件本体节点
- 组件自定义信号父节点可以连接子节点的信号，如：
  - 攻击组件（父） 攻击检测组件（子）
- 角色速度影响的组件，在角色根节点属性中添加该组件，在角色信号连接函数中连接信号
- 组件影响组件禁用相关的，在禁用发起组件（睡眠组件、胆小组件）中添加影响组件，在角色信号连接函数中连接信号
- 除上述情况以外，其余所有自定义信号都必须由角色本体在_ready()中对应的初始化函数中连接信号

__正常出战(Norm)角色死亡必须通过血量组件掉血死亡,禁止直接删除角色__
